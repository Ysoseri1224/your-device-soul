# Your Device Soul 使用指南

ysoul 是一个常驻在 Windows 桌面上的程序。它以一只黑猫的样子出现在屏幕上，知道你正在用哪个程序、在哪个项目里干活，会把你每天在这台电脑上做过的事记下来；你让它办事，它能读文件、跑命令、替你在别的程序里点按钮，但凡是会改动电脑的操作，都要你先点一下同意。

这份指南假设你第一次听说它。前三节讲它为什么存在、长什么样、用到的几个词是什么意思；后面是安装、日常使用、权限、模型和定制。

## 1. 为什么做这个

现在的 AI 助手大多待在一个聊天窗口里。用它们的时候有三件事一直不顺手。

第一，它们不认识你的电脑。每次都要你把情况讲一遍：装了什么软件、项目放在哪、刚才报了什么错。讲完这一次，下次还得再讲。

第二，它们不知道你此刻在干什么。你在编辑器里改了一下午代码，切到聊天窗口提问时，它对这一下午一无所知。

第三，在"动手"这件事上，现有的做法两头都不让人放心。只会聊天的助手什么都做不了，改个系统设置还得你照着它说的步骤自己点。能操作电脑的那一类，又常常是放开了让它跑，它删了什么、改了什么，事后才知道。

ysoul 想解决的就是这三件事：

- 它安装后会先把这台电脑查一遍（装了哪些软件、有哪些项目、开机启动了什么），存成清单，以后回答问题时自己去查。
- 它一直在后台留意你前台用的是哪个程序、哪个项目，并把一天的活动记成日记。你问"我昨天弄到哪了"，它有东西可查。
- 它能动手，但权限是你一处一处给的，由程序强制执行。任何会改动电脑的操作，它都先把"要做什么、在哪做、怎么撤销"写出来给你看，你点了同意才执行。

另外还有一个要求：它不能烦人。所以它绝大多数时间只是屏幕角落里的一只猫，不弹窗，不抢键盘，很少主动说话。

### 用起来是什么样

下面是几个具体的时刻。它们有一个共同点：你不用先向它交代背景，也不用自己照着步骤去点。

**早上坐下来，想不起昨天做到哪了。** 按快捷键，问一句"我昨天停在哪"。它去翻昨天的记录，回答类似这样："下午一直在 my-project 里，最后停在 form.ts，有两个测试还没通过。"这些是它昨天在后台记下的，你没有告诉过它。

**屏幕上弹出一个看不懂的报错。** 问"这报的什么错"。它看一眼你当前的窗口，告诉你原因。如果解决办法是改一项设置，它会把要做的操作写成一张确认单给你，你点同意，它来改；改完觉得不对，可以撤销。

**电脑开机越来越慢。** 说"看看开机都启动了什么，没用的帮我关掉"。它查出启动项，告诉你每一个是什么，把建议关掉的逐个列出来等你确认。它查的是这台电脑上实际的情况，给的不是一份通用教程。

**正在写一份文档，想找人看看。** 选中一段，说"帮我看看这段"。它读你选中的内容，把意见写在有问题的那句话旁边，你不用在聊天窗口和文档之间来回对照。

**有一件重复的杂事。** 说"把下载文件夹里的截图按月份归到 D:\pics"。它先列出打算移动哪些文件、移到哪里，你同意后执行。

**有一件更适合别的工具做的事。** 说"让 Claude Code 把这个项目里的错别字改掉"。它把这句话原样转交给那个工具，在你指定的项目里执行，开始之前同样先给你看一眼。

概括起来，它适合两类事：一类是关于"这台电脑"和"你最近在做什么"的问题，这些它平时已经记着；另一类是电脑上的各种操作，你说要什么结果，它去做，改动之前先问你。

## 2. 你会在屏幕上看到什么

ysoul 运行时，会在整个屏幕上盖一层透明的窗口。这层窗口上画着下面这些东西，其余地方鼠标点下去会直接穿过它，落到后面的程序上，所以它不影响你正常使用电脑。

**箱子。** 屏幕右下角有一个木箱，是猫的窝。用鼠标点一下箱子，会展开一个小面板，里面有它认为你现在在做什么、内存用了多少、今天的活动记录，以及几个按钮。箱子可以拖到别的位置。

**猫。** 一只黑猫。你在某个窗口里停留二十秒以上，它会从箱子里出来，跳到那个窗口的标题栏上坐着；窗口占满全屏时，它坐在任务栏上。它把各个窗口的上边缘当作可以落脚的台子，在它们之间走和跳。猫出来以后，箱子会缩到屏幕边上，只露出一小部分。你可以用鼠标把猫拎起来放到别处，也可以把它拖回箱子里。

**猫的姿势代表它的状态：**

| 姿势 | 含义 |
|---|---|
| 坐着 | 没有事 |
| 蜷成一团 | 你超过一分钟没有操作电脑，或者你打开了"这阵子别出声" |
| 举着一块牌子 | 有一张票在等你处理（"票"见下一节） |
| 坐着玩毛线球 | 你同意的操作正在执行 |
| 眼睛里和头顶冒星星 | 操作成功了 |
| 头顶三个感叹号 | 操作失败了 |
| 全身的毛竖起来 | 内存占用持续超过 93% |
| 伸爪子把一个杯子碰倒 | 它不赞成你让它做的事（它会说明理由；你坚持的话它照做） |

**其他会出现的小东西：**

- **此刻条**：箱子上方的一行小字，例如"你在：VS Code · my-project"。这是它对你当前活动的判断，判断错了你一眼就能看出来。
- **气泡**：它主动说的一句话，几秒后自己消失。
- **票**：一张卡片，上面写着它打算做的一个操作，等你点"做"或"不做"。
- **爪印**：箱子旁边的一排小爪印，每个代表今天执行过的一张票。点开可以看结果，也可以撤销。
- **夹在窗口上的纸条**：它留给你的一句和某个窗口有关的话，贴在那个窗口的上边缘，半小时后自己消失。
- **圈和批注**：你问"是哪个按钮""哪里写错了"时，它在屏幕上把那个位置圈出来，或者在那段文字旁边写一句话。

## 3. 先认识几个词

后面会反复用到下面几个词，这里先说清楚。

**票。** ysoul 要执行一个会改动电脑的操作之前，先生成的一张确认单。上面有四项内容：要做什么（一句话）、在哪里做（哪个目录、注册表哪一项、哪个服务）、能不能撤销、实际要运行的脚本（可以展开看）。你点"做"，它才执行；执行完，票上会留下运行结果和一个"撤回"按钮。你点"不做"，这张票作废。

**家的地图。** 一张权限表，记录这台电脑上每个位置 ysoul 可以做哪些事。每个位置有五项权限，分别是：看（读取内容）、放（新建文件）、改（修改已有文件）、扔（删除）、运行（执行里面的程序）。表里没有列出的位置，默认只能看，不能动。这张表存在一个普通的文本文件里，你可以随时查看和修改。

**私人目录。** 你指定的一批目录。ysoul 不能读取这些目录里的任何内容，连里面有哪些文件都看不到。它和"家的地图"的区别是：地图管的是"能不能改"，私人目录管的是"能不能看"。有一个例外：你亲手交给它的那一个文件，它可以看（见第 7 节）。

**记忆。** `memory` 文件夹。里面是 ysoul 自己写、自己维护的一批 Markdown 笔记：这台电脑的清单、你告诉过它的事、每天的活动总结、它想问你的问题。它每次思考时会带上其中最重要的几份，其余的需要时再去翻。这些都是普通文本文件，你可以用任何编辑器打开和修改。

**通道。** ysoul 自己不包含 AI 模型，它需要调用一个模型来思考。"通道"指的是一条可用的调用途径，例如你电脑上登录好的 Claude Code、你配置过的某家 API、本机运行的 Ollama。它会自动找出电脑上已有的通道，由你决定用哪一条。

**出生。** 安装后需要手动执行一次的初始化命令（`ysoul birth`）。它做两件事：把这台电脑查一遍并存成清单；让 ysoul 读完这些清单后，写下它对这台电脑和对自己的第一份描述。没有执行过这一步，它对这台电脑一无所知。

## 4. 安装和第一次启动

**运行环境：** Windows 10 或 11；PowerShell 7（Windows 自带的是 5.1，需要另外安装 7）；至少一条可用的模型通道（见第 9 节）。

**获取程序：** 从发布页下载压缩包并解压，里面有两个程序：

- `ysoul-app.exe`：桌面上的猫。
- `ysoul.exe`：命令行工具，负责思考、权限检查和执行操作。猫在后台也是调用它来工作的。

也可以自己编译，需要 Rust 和 Node：

```powershell
cd runtime;          cargo build --release
cd ..\app\src-tauri; cargo build --release
```

**第一步：启动猫。** 双击 `ysoul-app.exe`。第一次启动会弹出一个设置窗口，需要填三项：

1. **称呼**：它怎么称呼你。只用于称呼。
2. **私人目录**：窗口里会列出各个磁盘的顶层文件夹，点一下就加入私人目录；也可以手动输入路径，一行一个。
3. **模型**：窗口里会列出它在这台电脑上找到的通道。点左边的圆圈设置使用顺序（排第一的优先使用，调用失败时自动换下一条）。"跑腿"按钮用来指定处理零碎小任务的通道，可以选一条便宜的。

点"就这样"保存。以后可以在任务栏托盘的猫图标上点右键，选"设置"再次打开。

**第二步：执行"出生"。** 在解压目录里打开终端，运行：

```powershell
.\ysoul.exe birth
```

大约需要十分钟。完成后点一下箱子，选"聊聊"，可以开始和它对话。

**第三步（可选）：把几个入口装进系统。**

```powershell
.\ysoul.exe setup
```

这条命令不会直接安装任何东西。它会为下面每一项生成一张票，显示在桌面上，你逐个决定装不装，装了以后也能在票上撤销：

| 名称 | 作用 |
|---|---|
| `menu` | 在资源管理器的右键菜单里加一项"交给 ysoul" |
| `ys` | 在终端里可以用 `ys 你的问题` 直接提问 |
| `start` | 在开始菜单里加一项"问 ysoul"，之后按 Win 键输入 ysoul 就能调出输入框 |
| `claude`、`cursor`、`codex` | 让这几个 AI 编程工具每完成一轮工作后通知 ysoul 一声（只告诉它在哪个目录，不告诉它做了什么），这样它的日记里会有这些记录 |

只想装其中几项，就把名称写在后面，例如 `ysoul setup menu ys`。

## 5. 它平时自己会做的事

**根据你的操作做出的反应：**

| 你的操作 | 它的反应 |
|---|---|
| 在同一个窗口里停留超过 20 秒 | 从箱子里出来，坐到那个窗口的上边缘 |
| 切换到另一个窗口 | 几秒后跟到新窗口上 |
| 超过 1 分钟没有碰键盘和鼠标 | 原地蜷起来睡觉；你一动它就醒 |
| 超过 5 分钟没有操作 | 回到箱子里 |
| 用鼠标把它拎到别处 | 留在你放下的位置，直到你切换窗口 |
| 把它拖进箱子，或在菜单里选"叫它回箱子" | 留在箱子里，直到你叫它出来 |
| 全屏看视频、玩游戏 | 整层隐藏。如果有票在等你，会在屏幕右侧露出半个头 |
| 输入的文字延伸到它所在的位置 | 移到旁边没有文字的地方；找不到就回箱子 |

**它主动做的事：**

| 触发条件 | 它做什么 |
|---|---|
| 你离开超过 10 分钟后回来，或你在一件事上连续做了 40 分钟后切走 | 可能用气泡说一句话。它被要求大多数时候保持沉默，所以通常不说。两次之间至少间隔 20 分钟 |
| 内存占用连续半分钟超过 93% | 炸毛，并用气泡提醒一次 |
| 一张票等了 15 分钟没有处理 | 用气泡提醒一次，之后不再提醒 |
| 你进入一个它没见过的项目，或打开一个它没见过的程序 | 自己去查一下那是什么，在笔记里记几句。不出声。每天最多三次 |
| 你离开超过 30 分钟，并且当天的活动记录积累了十几条 | 把当天的活动整理成几句话的总结，存进笔记。每天最多两次 |

气泡上点一下左键，表示"知道了，这样说话可以"；点右键表示"别说了"，之后两小时内它不再主动开口。它会记住你对每句话的反应，用来调整以后说什么。

如果完全不想被打扰：在箱子上点右键，勾选"这阵子别出声"。

## 6. 怎么跟它说话

有三个入口，适合不同的场合。

**快速提问。** 按 `Ctrl+Alt+空格`，鼠标光标旁边会出现一个输入框。输入问题后按回车，输入框消失，键盘焦点回到你原来的程序；它的回答会显示在同一个位置，点一下就关闭。每次快速提问都是一场独立的对话，它不会把这次的问题和上一次的混在一起。

如果这个快捷键被别的程序占用，ysoul 会改用 `Ctrl+Alt+Y`。也可以点一下托盘里的猫图标，或者（装了 `start` 之后）按 Win 键输入 ysoul。

**连续对话。** 点箱子，再点"聊聊"，会打开一个对话面板。这里的对话是连续的，它记得前面说过什么。超过 45 分钟没有新消息，下次会开始一场新对话。

**终端。** 装了 `ys` 之后，在任何终端里输入 `ys 你的问题`。

两个输入框里都是回车发送，Shift+回车换行。

## 7. 怎么让它办事

直接用平常说话的方式告诉它。下面按"它需不需要你确认"分成三类。

### 不需要确认、立即执行的

- **打开程序。** 说"打开 DeepL"，或者只输入"DeepL"。这类请求不经过 AI 模型，程序直接按名称匹配后打开，所以很快。
- **打开文件、文件夹、网页。**
- **查询信息。** 例如"哪个进程最占内存""这个目录里有什么""这个项目现在在哪个分支"。它会现场运行只读的命令去查。
- **在别的程序里滚动页面、翻页。**

### 需要你在票上点"做"的

- 修改系统设置或注册表、删除文件、停止服务、安装或卸载软件。
- 在"家的地图"没有授权的位置新建或修改文件。
- 在别的程序里点按钮、填写内容、输入文字。
- 把一项任务转交给另一个 AI 工具（例如"让 Claude Code 把这个项目里的错别字改掉"）。

票上除了"做"和"不做"，在"操作别的程序"这一类票上还有第三个按钮**"这个程序以后都行"**。点了之后，它以后在那个程序里的操作不再逐次询问。另外，如果你在同一个程序里连续两次点了"做"，它也会自动按"以后都行"处理，并在票上告诉你。这个授权记在"家的地图"里，可以随时取消。

一件事如果分成好几步、中间需要你确认，你确认之后它会自动继续后面的步骤。

### 让它看某样东西

- **选中一段文字再提问。** 例如在浏览器里选中一句话，然后快速提问"这句是什么意思"。它能读到你选中的内容。
- **把文件交给它。** 三种方式：在资源管理器里右键文件选"交给 ysoul"；把文件拖到箱子上；在消息里直接写出文件的完整路径。用这三种方式交给它的文件，即使位于私人目录里它也可以读取。这个许可只对这一个文件有效，只能读不能改，半小时后失效。
- **让它看屏幕。** 说"你看这个"。它会对你当前的窗口截一张图，看完后删除。

### 查看和撤销它做过的事

箱子旁边的爪印对应今天执行过的票：黑色是成功，红色是失败，浅色是已撤销。点开任意一个可以看运行结果；如果这项操作可以撤销，票上有"撤回"按钮。超过五个时，较早的收在箱子面板的"今天动过的手"里。

### 命令行

`ysoul.exe` 也可以直接使用。常用的几条：

```powershell
ysoul say 你好             # 提一个问题
ysoul chat                # 在终端里连续对话
ysoul ticket              # 列出最近的票；ysoul ticket do|no|undo <编号> 对应 做/不做/撤回
ysoul where D:\some\path  # 查看某个路径的五项权限
ysoul run "git status"    # 把一条命令交给权限检查：只读的直接运行，其他的生成票
ysoul channel             # 查看和选择模型通道
ysoul app deepl           # 按名称查找程序，加 --open 则打开
```

`ysoul --help` 可以看到全部命令。

## 8. 它能碰什么，不能碰什么

| 操作 | 处理方式 |
|---|---|
| 读取文件、搜索目录、查看进程和服务、读取注册表、查看 git 状态和提交记录 | 直接执行，但执行前程序会检查目标位置是否允许"看" |
| 打开文件、网页、程序 | 直接执行 |
| 在别的程序里滚动、翻页 | 直接执行 |
| 在别的程序里点击、填写、输入 | 你授权过的程序直接执行；没授权过的生成票 |
| 修改注册表或系统设置、删除、停止服务、在未授权的位置写文件 | 生成票 |
| 任何无法确认是只读的命令 | 生成票 |
| 密码输入框、杀毒软件的窗口、系统的管理员权限确认窗口、聊天软件和邮件客户端 | 一律不操作 |
| 私人目录里的内容 | 不读取（你亲手交给它的那一个文件除外） |

**这些限制是怎么保证的。** 限制写在程序里。AI 模型每次要读、写一个文件，或者运行一条命令，这个请求都会先交给 `ysoul.exe` 里的一段检查代码，由它对照"家的地图"和私人目录名单决定放行还是拒绝。模型自己无法跳过这一步。

对于命令，检查代码用 PowerShell 自带的语法分析器把命令拆开来看。只有满足"单独一条命令、是已知的只读命令、参数都是直接写明的值"这几个条件的，才会直接运行。包含变量、拼接、多条语句的命令，程序无法确定它会访问哪里，一律生成票让你过目。

**怎么修改权限。** 点箱子，再点"家的地图"，会显示权限表，点任意一格即可切换允许或不允许。你也可以直接对它说"某某目录以后你可以改"，它会生成一张修改权限表的票，你确认后生效。它自己无法修改这张表。

## 9. 选择它用的模型

ysoul 会在四个地方寻找可用的通道：

| 来源 | 需要你做什么 |
|---|---|
| Claude Code | 已安装并登录，在终端里能运行 `claude` 命令 |
| cc-switch | 在 cc-switch 里添加过供应商 |
| 环境变量 | 设置了 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`OPENROUTER_API_KEY` 或 `DEEPSEEK_API_KEY` |
| Ollama | 本机正在运行 Ollama |

在设置窗口里选择，或者用命令行：

```powershell
ysoul channel                    # 列出找到的通道及其编号
ysoul channel use <编号> <编号>   # 设置使用顺序；前一条调用失败时自动换下一条
ysoul channel cheap <编号>        # 指定处理零碎小任务的通道
ysoul channel auto               # 恢复默认设置
```

**建议用 cc-switch 来管理。** [cc-switch](https://github.com/farion1231/cc-switch) 是一个用来给 Claude Code、Codex 等工具切换 API 供应商的小工具。它的用法是：安装后点"添加供应商"，选择应用类型，填入接口地址、API 密钥和模型名称并保存。之后回到 ysoul 的设置窗口点"重新找"，这条供应商就会出现在列表里。好处是密钥只需要在 cc-switch 里填一次，ysoul 用的时候直接读取，自己不保存密钥，只保存你选了哪一条。

**兼容性。** ysoul 支持三种接口格式：通过 Claude Code 调用、Anthropic 的 Messages 接口、OpenAI 的 chat/completions 接口。市面上大多数服务都兼容后两种之一。如果某个中转服务只接受来自 Claude Code 客户端的请求，而你电脑上装了 Claude Code，ysoul 会自动改为通过 Claude Code 去调用它。

一个限制：让它看截图的功能，目前只有通过 Claude Code 调用时才可用。

## 10. 按自己的习惯调整

**外观。** 在猫或箱子上点右键：

- 猫的大小：小、中、大。
- 猫的描边：不描、细白边、粗白边。在深色背景上，白边能让黑猫更容易看清。

**称呼、私人目录、模型。** 托盘图标右键，选"设置"。

**它的说话方式和行事规则。** 都写在 `prompts/system.md` 这个文本文件里，例如"回答要简短""不要主动提建议，除非有具体的修改方案"。直接修改这个文件即可，下一次对话生效，不需要重新编译。

**它的性格。** `seed/temperament.md` 是你在"出生"之前写给它的一段话，描述你希望它是什么样的。"出生"时它会读这段话，然后自己写一份自我描述存进记忆。出生以后想调整，改 `memory/me/core.md`。

**它记住的内容。** `memory` 文件夹里的笔记都可以直接修改或删除。

**各种时间和阈值**（多久算离开、多久说一次话、内存多少算过高）在源代码里，需要修改后重新编译：

| 想调整的 | 位置 |
|---|---|
| 多久算走开、一段活动多短就不记 | `runtime/src/pulse.rs` 开头的几个常量 |
| 说话的间隔、内存阈值、猫什么时候出箱 | `app/ui/app.js` 里的 `behave` 和 `onOccasion` 两个函数 |
| 哪些命令被认为是只读的 | `runtime/src/shell.rs` 开头的三个列表 |
| 允许它在别的程序里按哪些键 | `runtime/src/uia.ps1` 里的按键表 |

**猫的画法和动作。** 猫的图形和动画定义在 `design/ysoul-surface-lab.html` 里。这是一个可以直接在浏览器里打开操作的网页。修改后运行 `node app/tools/extract-cat.mjs`，把改动同步到程序里。

## 11. 你的数据去了哪里

**留在本机、不会离开的：**

- `local` 文件夹里的全部内容：每一张票、操作记录、发送给模型的每一次请求的副本、截图、按时间记录的原始活动日志（包含窗口标题）。
- API 密钥。ysoul 每次调用时现读，只存在于内存中。

**会离开本机的，只有两种情况：**

- 发送给模型的请求。发送前，程序会把其中形似密钥、邮箱地址、账号 ID 的内容替换成占位符。每次请求的原文都会在 `local/outbound` 里存一份，你可以随时查看它到底发了什么。
- 如果你自己把这个文件夹用 git 推送到远程仓库。`.gitignore` 默认已经排除了 `local` 和原始活动日志。

**它不做的事：**

- 不记录聊天软件和邮件客户端的窗口标题，不读取、不截取这些窗口的内容。
- 不使用麦克风。
- 不持续截屏。只有你要求它看屏幕时才截一张，看完删除。
- 不把密钥内容、你的真实姓名、邮箱、账号写进记忆。

**两个辅助脚本：**

- `tools/suggest-private.ps1`：扫描各个磁盘的顶层文件夹，把名称看起来像私人内容的列出来（聊天软件的数据目录、文档、照片、下载等），帮你在"出生"之前把私人目录设置完整。不加参数时只显示结果，不做任何修改。
- `tools/audit.ps1`：如果你打算把自己的这份文件夹（包含记忆）推送到远程仓库，先运行它。它会检查其中有没有邮箱地址、形似密钥的字符串、你的 Windows 用户名和私人目录的名称。

## 12. 目前做不到的

- **只支持 Windows。**
- **只支持一个显示器。** 接了多个显示器时，它只出现在主显示器上。
- **只能操作当前在最前面的那个窗口。**
- **有些程序它无法操作。** 它操作别的程序依靠的是 Windows 为读屏软件提供的接口。部分游戏、一些老式编辑器和自己绘制界面的程序不提供这个接口，它就看不到里面的按钮和文字，这时只能通过截图来了解画面。
- **写在文字旁边的批注，在某些程序里不会跟着文字移动。** 原因同上：程序不提供文字的位置信息。
- **在终端里用鼠标选中的文字，它有时读不到。** 像 Claude Code 这样接管了鼠标的终端程序，选中的高亮是程序自己画的，系统拿不到。按住 Shift 再拖动选择，通常可以解决。
- **稍微复杂一点的只读命令也会生成票。** 权限检查的规则偏保守，带计算或变量的查询命令会被当作"无法确认"处理。
- **只有黑猫这一种外观。**
- **发布的程序没有数字签名。** 第一次运行时 Windows 会弹出安全提示。

## 13. 仓库里有什么

| 文件夹 | 内容 |
|---|---|
| `app` | 桌面上的猫。`ui` 是界面，`src-tauri` 是后端，`tools` 里是从设计稿生成界面代码的脚本 |
| `runtime` | `ysoul.exe` 的源代码：记忆、模型通道、活动感知、权限检查、操作执行 |
| `memory` | 它的笔记 |
| `prompts` | 给模型的指令 |
| `seed` | 你在"出生"前写给它的话 |
| `sensors` | "出生"时用来清点这台电脑的脚本 |
| `design` | 界面和猫的设计稿，可以在浏览器里直接打开 |
| `tools` | 上一节提到的两个辅助脚本 |
| `local` | 只存在于本机的数据，不进入 git |
