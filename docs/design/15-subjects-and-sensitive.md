# Device Soul（ysoul）— 立新学科的流程，和敏感内容怎么办

> 2026-10-12。两件各自不大、但一直欠着的设计。
> 第一件机主说过："立新学科的实际流程不应该你来设计吗？"第二件机主说过："敏感的判断先定密钥，个人信息现在也算敏感内容，加密我没想好。"

---

## 一、立新学科

`06` 第五节定了四条规则：骨架固定、学科可长；先积累、后立科；立科是郑重的动作；定期整理。那里没写的是"实际怎么走"。这里补上。

### 1. 平时：先进"未归类"

它学到一条关于世界的知识（不是关于机主，也不是关于这台机器），记进 `learned/unsorted.md`，一条一行：日期、内容、从哪知道的。

不分类，不起标题。这是为了防 `06` 里说的"滥开"：模型很爱新建分类。在这里它没有新建的机会。

### 2. 起意：在反思里

反思（`13` 第六节）的第四件事：读一遍"未归类"。有没有一个主题符合这两条：

- 这个主题的条目已经多到在"未归类"里找起来费劲；
- 条目之间开始有结构：有先后、有因果、有"这条修正了那条"。

两条都符合才起意。不设数量，这是机主的意思（"硬规则永远是僵硬的"）。只有一条符合不算：多而散的是杂记，少而有结构的还能再等等。

### 3. 问：一句话，不催

起意后，往 `inbox/questions.md` 写一条：

> 我攒了十来条关于 X 的，彼此开始连得上了。想给它单开一块，叫 `<英文名>`。行吗？

下一次机主跟它说话时，它在回话末尾提这一句。只提一次。机主没接话就算了，这一条留在 inbox 里，下回反思时如果这个主题又长了才再提。

不用气泡提。气泡是闲话，立科是郑重的事。

### 4. 立

机主说行（或者说"这种事你自己定"，那以后就不用问了，记进 `you/said.md`）：

1. 建 `learned/<英文名>/index.md`。开头三行：这一科是什么、为什么立（引用当时的条目数和那句问话）、哪天立的。下面是这一科的分索引。
2. 把"未归类"里属于这一科的条目搬过去。能合成一篇的合成一篇，各篇之间用 `[[链接]]` 连起来。"未归类"里原来的行删掉。
3. 总索引 `index.md` 加一行，指向这一科的分索引。
4. `me/timeline.md` 记一笔："某年某月某日，立了 X 这一科，因为……"
5. 回话里告诉机主一声，一句。

名字用英文小写、短横线连接，一旦定了不改。要改名只在整理时做，并且把所有链接一并改掉。这是防"命名漂移"。

### 5. 撤和并

反思时也看已有的学科：

- 一科很久没添东西，而且只有两三篇：提议并回"未归类"。同样先问。
- 两科说的是同一件事：提议并成一科，名字留用得久的那个。
- 一科太大，里面明显分成了两块：提议拆。

撤、并、拆和立一样，记进 timeline，告诉机主。

### 现状

反思的提示里已经有前三件事，第四件（读"未归类"、起意）这次一并加上了。`learned/` 现在是空的，所以这条流程一次都还没走过。

## 二、敏感内容

### 先把"敏感内容"到底指什么数清楚

`02` 第五节写的是"只有敏感内容才加密"，用 DPAPI。那是在它什么都还不能做的时候写的。现在它能看、能动手了，重新数一遍它手里可能有哪些敏感的东西：

| 东西 | 在哪 | 现在怎么处理的 |
|---|---|---|
| 密钥、令牌、密码的内容 | 机器上各处的配置文件 | 普查时遮掉；发给模型前再遮一遍；它的规矩是不写进笔记。OpenRouter 的密钥运行时现读，不落盘 |
| 机主的个人信息（姓名、邮箱、账号、身份） | 路径里、文件名里、窗口标题里 | 普查时遮掉；它的规矩是不猜不记不提 |
| 聊天和邮件 | 那些程序的窗口 | 标题不记、不截 |
| 私人目录的内容 | 机主列的那份名单 | 它看不了，由程序拦 |
| "看一眼"截的图 | `local/tmp/look.png` | 见下 |
| 票里的脚本和输出 | `local/tickets/` | 明文，不进仓库 |
| 发给模型的每一次原文 | `local/outbound/` | 遮过之后的明文，不进仓库 |
| 日记里的窗口标题 | `memory/diary/` | 明文，进仓库（私有） |

### 方案：能不留的不留，留下的不出这台机器，不加密

我的建议是**不做加密这一层**，理由三条：

1. **该加密的东西，现在的做法是根本不留。**密钥内容、个人信息、聊天内容，都在进入它的记忆之前就被遮掉或者拦下了。没有留下来的东西，不需要加密。这比加密强：加密的东西还在，只是锁着；不留的东西不在。
2. **DPAPI 防不了它该防的。**`02` 自己写了：它防的是别的账户和硬盘被拷走，防不了以机主身份运行的程序。而这台机器上会去读 ysoul 文件的，恰恰都是以机主身份运行的程序。硬盘被拷走这种情况，该由整盘加密（BitLocker）来管，不是由 ysoul 给自己的几个文件单独上锁。
3. **加密和"机主能直接看、直接改"冲突。**`06` 的第五条原则是笔记库就是一堆机主能用任何编辑器打开的文本。加了密的文件做不到这一点。

所以落到实处是三条规矩，其中两条已经在做，一条这次补上：

- **不留**：密钥内容、个人信息、聊天和邮件内容，不进记忆。【已做】
- **不出机器**：`local/` 整个目录不进仓库（票、动作记录、发信留底、截图、闲话记录）。出这台机器的只有两条路：发给模型的那一份（遮过），和推到机主私有仓库的那一份（记忆和代码）。【已做】
- **用完就删**："看一眼"截的图，那一轮对话结束就删掉。它看过了，要记的是它看懂的那句话，不是那张图。【这次补上】

### 留给机主定的

只有一件，而且不急：**日记进不进仓库**。日记里有窗口标题，也就是你看过的网页标题、打开过的文件名。现在它和其他记忆一样会被推到你的私有仓库。你说过浏览器页面不算隐私，所以我按"进"做了。哪天你觉得不合适，把 `memory/diary/` 加进 `.gitignore` 就行，别的都不用改。
